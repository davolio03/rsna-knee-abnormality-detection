# E043 — Audited one-GPU continuation checkpoint migration

## Objective and scope
Prepare an explicit one-GPU migration of the verified private RadImageNet epoch-one checkpoint for the authorized next local epoch. Preserve the frozen recipe source and strict resume checks. This migration does not start training, build the full cache, or claim bitwise-equivalent continuation across runtimes.

## Hypothesis and baseline
- **Hypothesis:** The epoch-one checkpoint can be continued on the single local CUDA device without changing model weights, Adam history/state, metric history, Python/NumPy/CPU Torch RNG state, or completed-epoch count, provided the full source-backed fingerprint is recomputed for the exact local runtime and only Kaggle's active CUDA RNG state is mapped to local device 0.
- **Baseline:** Original private checkpoint SHA-256 `83518ebe59f8a3ecf39b2d8da35aa4c618afeeb04a78b315b5cda13ff56014a8`; original fingerprint `1275e1e977188df71008cc4814825f170bd9dc84f76fd4143e87479ae38080be`; one completed epoch; original runtime Python 3.13.15 / PyTorch 2.11.0+cu128 / NumPy 2.1.3 / CUDA 12.8.
- **Changed variable:** Runtime/device binding only. The migrator creates a new copy with a newly computed local fingerprint and maps the original active CUDA state 0 to the one visible local CUDA device 0. Original checkpoint bytes remain unchanged; the original unused CUDA state remains in that original file and is audited by a digest in the migration receipt.
- **Expected mechanism:** Verify and extract the exact 29-member source archive into a new private source root; reconstruct the original full-cohort selection fingerprint using the explicitly recorded Kaggle runtime; pass the original checkpoint through the frozen runner's unchanged `_read_resume`; compute the local fingerprint with the frozen runner; strictly validate the migrated copy through the same reader; load model/Adam state against the pinned RadImageNet model and validate optimizer groups/state; restore the mapped RNG using the frozen runner on the actual one-GPU environment.

## Implementation and verification
The migration utility is `scripts/local_radimagenet_checkpoint_migration.py`. It defaults to read-only plan output; `--execute` writes a fresh migration bundle containing the migrated checkpoint and a privacy-safe receipt. It rejects any runtime/version or visible-device-count mismatch, fingerprint mismatch, source/member/weight/cohort pin mismatch, symlinks, extra source members, or non-fresh outputs. It does not monkeypatch frozen runner functions or weaken resume guards. The training FP32/no-autocast/no-TF32 policy is recorded and applied only inside a temporary process-local context during the RNG restoration check; existing process precision settings are restored afterward.

## Limits and next step
This is checkpoint compatibility evidence, not an epoch-two run and not a claim of bitwise identity across Python versions or hardware. The single-study cached forward/backward/Adam benchmark is separately recorded in E042 (1.935 seconds, 351.2 MiB allocated / 392 MiB reserved, FP32 and TF32 off); it advanced optimizer state only in discarded RAM and did not restore RNG or save a checkpoint. Full cache aggregation/coverage verification and independent review of this migration remain required before the parent launches the one authorized full local epoch.
