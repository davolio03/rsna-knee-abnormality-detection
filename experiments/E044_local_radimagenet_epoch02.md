# E044 — Local RadImageNet epoch two continuation

## Hypothesis and baseline
Resume the verified one-epoch RadImageNet checkpoint on the same fold-0 cohort using the exact seven-part, study-ordered selected-image cache. Baseline is the unchanged epoch-one checkpoint, whose expected SHA-256 is `83518ebe59f8a3ecf39b2d8da35aa4c618afeeb04a78b315b5cda13ff56014a8` and whose frozen-recipe fingerprint is `1275e1e977188df71008cc4814825f170bd9dc84f76fd4143e87479ae38080be`.

## Fixed protocol
Use the pinned 29-file source archive, 224-pixel preprocessing, maximum eight selected slices per series, frozen mean-slice/mean-series logit pooling, float32 without autocast or TF32, and the existing ResNet50 head/layer4 learning rates. Preserve the original model, Adam state, history and checkpoint. The one-GPU continuation may change only the explicitly audited runtime fingerprint and active CUDA RNG mapping. Train exactly one incremental epoch (epoch two of five), then stop; no cold start, full epoch beyond this bounded authorization, Gold-58, remote run, or new data transfer.

## Validation and execution status
The adapter re-hashes the pinned source/manifest/folds/plan and seven ZIP archives, checks ZIP CRCs and archive-manifest membership against the complete canonical fold-0 selection, and validates the independently generated aggregate proof and each part proof. The full validated cohort is 4,298 studies, 23,765 series and 190,120 slices; train 2,850, validation 1,448; no overlap and zero Gold intersection. The cache dataset implements the frozen runner's documented `dataset_factory` seam and loads only selected cached arrays, never DICOMs. A receipt binds the external adapter/CLI, cache plan/archive/proof hashes, original and migrated checkpoint hashes, and the fingerprint recomputed by the frozen native runner.

Strict tests observed RED before implementation and then passed **7 tests** with `data/private/local-cuda-env/Scripts/python.exe -m unittest tests.test_local_radimagenet_epoch_adapter` (106.791 s). A follow-up mocked-native regression observed the actual native call with TF32 disabled, cuDNN benchmark disabled, highest float32 matmul precision, and autocast off; separate guard cases reject unavailable/multiple GPUs or under 3 GiB free. The planning-default CLI passed in the pinned CUDA runtime; it reported one completed epoch, one incremental epoch, target five, exact resume payload/runtime, live GPU free/total memory, measured one-study benchmark and an eight-hour runtime cap, while leaving the epoch output absent. `compileall` and `git diff --check` passed.

The bounded actual-cache GPU benchmark used one training study (five series, forty slices, three observed targets), restored epoch-one model and Adam state, checked the trainable head/layer4 gradients and frozen layer3 behavior, performed one forward/backward/Adam step in discarded RAM, and saved no checkpoint. It passed on the RTX 3060 Laptop GPU / PyTorch 2.11.0+cu128 / CUDA 12.8 in 1.546 seconds; peak allocated/reserved memory was 351.2/392.0 MiB. Adam step advanced 2850→2851 only in RAM. Native fingerprint recomputed by the frozen runner was `5c08ab6be89773802ce4f18fa2209a7e85ec88f2703b5caaded9bd940025a920`. FP32, autocast off, TF32 off. The private benchmark receipt binds the external adapter hashes, cache/part-proof/archive pins, migration receipt and checkpoint hashes. The original checkpoint remains SHA-256 `83518ebe59f8a3ecf39b2d8da35aa4c618afeeb04a78b315b5cda13ff56014a8`; the migrated checkpoint is SHA-256 `1001152893d44aa52d0ec2083d00b22b9ffc2ae124c8ec5afd46065e923f80b2`.

## Results and limits
Before invoking the frozen native runner, the training path now independently enforces the migrated target runtime, exactly one visible CUDA device, at least 3 GiB free GPU memory, FP32/highest matmul precision, TF32 off, cuDNN benchmark off, and autocast off. The mocked-native test inspects these actual invocation-time settings. This benchmark is a plumbing/runtime feasibility check only, not a training epoch or performance comparison. The five-epoch target is not complete. No epoch-two training has been launched. Parent independent verification remains required before the separately authorized single-epoch launch.
